# M02: Canonical identities and immutable storage

These scenarios are product test designs, not executed tests.

## CAN-001: Canonical object order

Given: Objects have equal key/value pairs in different insertion orders.

When: The encoder serializes them.

Then: Their canonical bytes and action identities match.

Required platform roles: portable.

## CAN-002: Preserve array order

Given: Arrays contain equal elements in different orders.

When: The encoder serializes them.

Then: The resulting bytes and identities differ.

Required platform roles: portable.

## CAN-003: Reject invalid numbers

Given: Inputs contain floats, NaN, infinity, negative zero, or unsafe integers.

When: The core parses canonical values.

Then: Each invalid value fails before identity calculation.

Required platform roles: portable.

## CAN-004: Reject duplicate keys

Given: Raw JSON repeats an object key.

When: The parser reads it.

Then: The parser rejects the duplicate rather than retaining one value.

Required platform roles: portable.

## CAN-005: Preserve Unicode bytes

Given: Valid Unicode strings differ by normalization form.

When: The encoder hashes them.

Then: It preserves their scalar values and never normalizes silently.

Required platform roles: portable.

## CAN-006: Reject invalid Unicode

Given: A value contains an unpaired surrogate.

When: The encoder receives it.

Then: It returns a defined validation error.

Required platform roles: portable.

## CAN-007: Apply digest domains

Given: The same canonical bytes are used for tree, action, and plan values.

When: Their identities are calculated.

Then: The versioned NUL-terminated domain prefixes produce distinct digests.

Required platform roles: portable.

## CAN-008: Verify raw blob bytes

Given: Empty, binary, and text fixture blobs exist.

When: The store imports them.

Then: Their digests match independent golden vectors.

Required platform roles: portable.

## CAN-009: Reject unsafe portable paths

Given: Traversal, drive, alternate stream, and reserved-name fixtures exist.

When: Portable tree validation runs.

Then: It rejects invalid paths without filesystem effects.

Required platform roles: portable.

## CAN-010: Validate tree structure

Given: One tree contains duplicate paths or a file ancestor of another entry.

When: The tree is validated.

Then: It fails before materialization.

Required platform roles: portable.

## CAS-001: Publish verified bytes atomically

Given: A valid blob arrives through staging.

When: The store commits it.

Then: Only a complete verified object becomes addressable.

Required platform roles: portable.

## CAS-002: Reject corrupt bytes

Given: Downloaded bytes differ from the expected digest.

When: Import attempts commitment.

Then: No trusted object appears and the mismatch is reported.

Required platform roles: portable.

## CAS-003: Converge concurrent writes

Given: Two writers import the same digest.

When: Both complete concurrently.

Then: One valid immutable object remains with no corrupt intermediate state.

Required platform roles: portable.

## CAS-004: Recover interrupted import

Given: A process stops at each import transaction point.

When: The store reopens.

Then: Recovery exposes only complete committed objects.

Required platform roles: portable.

## CAS-005: Protect immutable inputs

Given: A worker receives a writable workspace from a stored tree.

When: It changes workspace files.

Then: The original store bytes remain unchanged.

Required platform roles: portable.

## CAS-006: Preserve runtime references

Given: A package needs a runtime dependency after compilation.

When: Its closure is installed and collected.

Then: The dependency remains reachable and execution succeeds.

Required platform roles: portable.

## CAS-007: Handle full disk

Given: A fixture storage layer returns disk-full errors.

When: Import or metadata commitment runs.

Then: The old valid state remains recoverable and no partial object becomes trusted.

Required platform roles: portable.

## CAS-008: Respect destination semantics

Given: A valid Linux tree has Windows-incompatible names.

When: Windows materialization is requested.

Then: The operation fails explicitly without silent name rewriting.

Required platform roles: portable.
