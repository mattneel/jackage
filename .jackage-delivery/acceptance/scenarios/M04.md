# M04: TypeScript and QuickJS-NG evaluation

These scenarios are product test designs, not executed tests.

## EVAL-001: Transform real TypeScript

Given: A module contains types, interfaces, and imports.

When: The pinned transformation pipeline runs.

Then: QuickJS-NG receives valid JavaScript and evaluates the intended declarations.

Required platform roles: portable.

## EVAL-002: Separate type checks

Given: A syntactically valid module has a type error.

When: The declared type-check stage runs.

Then: It fails even if syntax transformation alone succeeds.

Required platform roles: portable.

## EVAL-003: Resolve locked imports

Given: A configuration imports a declared locked module.

When: Evaluation runs offline.

Then: It uses the exact module artifact and does not consult global packages.

Required platform roles: portable.

## EVAL-004: Deny undeclared imports

Given: A module requests a network URL or escaped host path.

When: The loader resolves it.

Then: Policy denies the import before data or process access.

Required platform roles: portable.

## EVAL-005: Deny ambient effects

Given: Configuration attempts time, randomness, host environment, files, and processes.

When: It executes in the evaluator.

Then: Undeclared effects fail and no host secret is exposed.

Required platform roles: portable.

## EVAL-006: Produce repeatable plans

Given: Equal source modules and declared inputs exist.

When: Independent evaluation workers run.

Then: Their canonical plan digests match.

Required platform roles: portable.

## EVAL-007: Stop infinite evaluation

Given: A module loops forever.

When: Evaluation exceeds its budget.

Then: The worker stops within the enforced deadline and publishes no plan.

Required platform roles: portable.

## EVAL-008: Bound allocation

Given: A module exhausts its allowed heap or stack.

When: The limit is reached.

Then: The host reports a resource failure and releases worker resources.

Required platform roles: portable.

## EVAL-009: Reject active values

Given: Results contain functions, cycles, accessors, prototypes, or unresolved promises.

When: The host extracts the plan.

Then: It accepts only inert schema-valid data without uncontrolled callbacks.

Required platform roles: portable.

## EVAL-010: Reject untrusted bytecode

Given: A channel supplies engine bytecode as configuration.

When: Evaluation is requested.

Then: The source-only policy refuses it.

Required platform roles: portable.

## EVAL-011: Key local evaluator cache

Given: The engine, transformer, options, or source changes.

When: Cached evaluation is considered.

Then: The changed identity prevents stale bytecode or plan reuse.

Required platform roles: portable.
