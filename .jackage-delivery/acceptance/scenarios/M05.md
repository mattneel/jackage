# M05: Resolution, plans, and lockfiles

These scenarios are product test designs, not executed tests.

## PLAN-001: Resolve exact closure

Given: A fixture graph contains compatible version candidates.

When: Resolution runs twice.

Then: It selects the same exact namespaced closure.

Required platform roles: portable.

## PLAN-002: Explain conflicts

Given: A graph has incompatible dependency constraints.

When: Resolution runs.

Then: A stable explanation identifies the conflicting dependencies.

Required platform roles: portable.

## PLAN-003: Preserve namespaces

Given: Two repositories publish the same package name.

When: A namespaced dependency resolves.

Then: The unrelated repository cannot satisfy it.

Required platform roles: portable.

## PLAN-004: Reject graph cycles

Given: Actions or dependencies contain a prohibited cycle.

When: Plan validation runs.

Then: It reports the cycle before execution.

Required platform roles: portable.

## PLAN-005: Lock complete inputs

Given: A project uses source, tools, evaluator modules, and a platform SDK.

When: A lockfile is committed.

Then: Every required input has an exact identity and provenance boundary.

Required platform roles: portable.

## PLAN-006: Refuse floating locked input

Given: A locked source contains only master or latest.

When: Locked execution begins.

Then: Validation refuses the unresolved identity.

Required platform roles: portable.

## PLAN-007: Honor locked mode

Given: New metadata offers different versions.

When: A locked task runs.

Then: It neither changes the lock nor silently re-resolves dependencies.

Required platform roles: portable.

## PLAN-008: Separate action and artifact identity

Given: Equal action identities produce different output bytes.

When: Results enter the cache.

Then: The discrepancy remains visible and cannot silently replace an earlier result.

Required platform roles: portable.

## PLAN-009: Schedule dependencies

Given: A graph includes independent and dependent actions.

When: The scheduler runs with bounded concurrency.

Then: It executes only ready nodes and respects dependencies and limits.

Required platform roles: portable.

## PLAN-010: Separate platforms

Given: A Linux action emits a Windows executable.

When: The test plan is selected.

Then: Native Windows tests require a compatible executor rather than a Linux compile result.

Required platform roles: portable.

## PLAN-011: Preserve cache policy

Given: A cached result lacks the requested release provenance.

When: The scheduler considers a hit.

Then: It rejects the incompatible hit or executes a qualified action.

Required platform roles: portable.
