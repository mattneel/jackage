# M07: Repository trust and local channels

These scenarios are product test designs, not executed tests.

## TRUST-001: Require root enrollment

Given: A new repository has no trusted root.

When: Noninteractive installation begins.

Then: It fails without trusting HTTPS or a self-provided checksum alone.

Required platform roles: portable.

## TRUST-002: Accept authorized metadata

Given: Valid root, timestamp, snapshot, and targets metadata exist.

When: The client updates.

Then: It selects only artifacts authorized by the trusted metadata chain.

Required platform roles: portable.

## TRUST-003: Reject bad signatures

Given: Metadata lacks its required signatures or threshold.

When: Verification runs.

Then: The update fails without modifying trusted state.

Required platform roles: portable.

## TRUST-004: Reject rollback

Given: A repository serves older verified metadata after a newer version.

When: The client updates.

Then: Persisted rollback protection rejects it.

Required platform roles: portable.

## TRUST-005: Reject expiry

Given: Metadata exceeds its permitted validity period.

When: An online update occurs.

Then: The client reports expiry and does not silently use stale metadata.

Required platform roles: portable.

## TRUST-006: Reject mixed snapshots

Given: Valid metadata files come from incompatible snapshots.

When: The client assembles an update.

Then: Hash and version checks reject the mixture.

Required platform roles: portable.

## TRUST-007: Rotate roots safely

Given: An authorized root rotation exists.

When: The client updates across interruption points.

Then: Only verified sequential root state becomes trusted.

Required platform roles: portable.

## TRUST-008: Distinguish offline execution

Given: A previously trusted installed artifact exists but online metadata expired.

When: Offline run and online update are requested separately.

Then: Each follows its explicit policy without claiming fresh metadata.

Required platform roles: portable.

## TRUST-009: Bound and verify downloads

Given: An asset has a declared length and digest.

When: Transfer truncates, expands, or returns different bytes.

Then: The client rejects it before store publication.

Required platform roles: portable.

## TRUST-010: Reject archive attacks

Given: Local fixtures contain traversal, links, devices, duplicates, and excessive expansion.

When: Extraction runs in a disposable root.

Then: No file escapes and limits stop unsafe extraction.

Required platform roles: portable.

## TRUST-011: Protect auth redirects

Given: An authenticated request redirects to an unrelated origin.

When: The HTTP adapter follows allowed redirects.

Then: It does not forward credentials across the trust boundary.

Required platform roles: portable.

## TRUST-012: Resist cache poisoning

Given: An untrusted cache advertises a result for a known action.

When: A release action considers the result.

Then: Required provenance checks prevent unauthorized acceptance.

Required platform roles: portable.
