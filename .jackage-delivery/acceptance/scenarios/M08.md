# M08: Strict Linux execution and verified transport

These scenarios are product test designs, not executed tests.

## STRICT-001: Deny undeclared filesystem

Given: A strict Linux action attempts host-file reads.

When: The real reference backend executes it.

Then: Reads outside declared roots fail and the behavior is captured.

Required platform roles: linux-x86_64.

## STRICT-002: Deny network

Given: A strict action attempts outbound and host-loopback connections.

When: The real backend executes it.

Then: Undeclared network access fails under the documented perimeter.

Required platform roles: linux-x86_64.

## STRICT-003: Isolate writable state

Given: Two strict actions use equal input trees.

When: One attempts to mutate inputs or the other's workspace.

Then: The attempt fails or remains private with unchanged store inputs.

Required platform roles: linux-x86_64.

## STRICT-004: Use stable logical paths

Given: Equal actions execute from different physical checkout roots.

When: Their outputs are compared.

Then: Declared path-independent artifacts match or the limitation remains explicit.

Required platform roles: linux-x86_64.

## STRICT-005: Enforce resources

Given: A strict process exceeds memory, process, or time limits.

When: Limits trigger.

Then: The action stops with a defined result and no orphaned descendants.

Required platform roles: linux-x86_64.

## STRICT-006: Authenticate workers

Given: A fake endpoint presents an untrusted identity.

When: The client requests remote execution.

Then: Connection authorization fails before source or credentials transfer.

Required platform roles: portable.

## STRICT-007: Verify returned artifacts

Given: A remote worker returns corrupt or undeclared outputs.

When: The client collects results.

Then: It rejects them before trusted store or cache commitment.

Required platform roles: portable.

## STRICT-008: Handle transport interruption

Given: A transfer or execution stream disconnects.

When: The client reconnects.

Then: It reconciles the action and verifies resumed data rather than guessing success.

Required platform roles: portable.

## STRICT-009: Cross Windows to Linux

Given: The actual Windows client requests a Linux action.

When: The declared transport executes it.

Then: Inputs materialize on Linux-native storage and validated results return.

Required platform roles: host.

## STRICT-010: Reject fake capabilities

Given: A backend claims capabilities without the required support status.

When: A strict action is matched.

Then: The core refuses unsupported or incompatible guarantees.

Required platform roles: portable.
