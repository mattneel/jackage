# M10: Portable and OCI package backends

These scenarios are product test designs, not executed tests.

## PACK-001: Plan package actions

Given: An artifact tree is ready.

When: A package backend describes an output.

Then: Its tools and effects appear as ordinary declared actions.

Required platform roles: portable.

## PACK-002: Build deterministic ZIP

Given: Equal input trees have different host enumeration orders and times.

When: ZIP creation repeats.

Then: The declared unsigned archive bytes match.

Required platform roles: portable.

## PACK-003: Build deterministic tar

Given: A tree includes executable files, directories, and supported links.

When: Tar creation repeats.

Then: Metadata policy and archive bytes match.

Required platform roles: portable.

## PACK-004: Round-trip tree

Given: A safe portable archive is built.

When: It is extracted through the product validator.

Then: The resulting supported tree identity matches the original.

Required platform roles: portable.

## PACK-005: Construct OCI layout

Given: A runtime closure and image configuration exist.

When: The OCI backend runs.

Then: A valid image layout with verified descriptor digests results.

Required platform roles: portable.

## PACK-006: Preserve OCI platform

Given: Image outputs target different architectures.

When: The backend creates configuration and an index.

Then: Each descriptor has the correct platform and validated digest.

Required platform roles: portable.

## PACK-007: Exclude build-only inputs

Given: A package has build and runtime dependencies.

When: Its release image is assembled.

Then: Only the declared runtime closure enters the payload.

Required platform roles: portable.

## PACK-008: Separate signing

Given: An unsigned package is reproducible.

When: A signing action runs with test authority.

Then: Unsigned and signed identities remain distinct with explicit envelope policy.

Required platform roles: portable.

## PACK-009: Inspect real image

Given: A Jackage-produced OCI image exists.

When: A compatible actual runtime starts it.

Then: Its declared entry point runs and expected dependencies exist.

Required platform roles: linux-x86_64.
