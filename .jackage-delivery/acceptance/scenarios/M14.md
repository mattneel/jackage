# M14: GitHub channels and authorized publication

These scenarios are product test designs, not executed tests.

## GH-001: Discover repository channel

Given: A fixture GitHub API serves a pinned discovery descriptor.

When: The user-style repo URL is resolved.

Then: The client records the descriptor revision and separately verifies trust.

Required platform roles: portable.

## GH-002: Use Pages-only channel

Given: A static fixture hosts metadata and artifact assets.

When: Install resolves through it.

Then: The complete verified package installs without a custom server.

Required platform roles: portable.

## GH-003: Use Releases-only channel

Given: Release fixtures host versioned metadata and assets.

When: Install resolves through discovery.

Then: The complete verified package installs without Pages.

Required platform roles: portable.

## GH-004: Use hybrid channel

Given: Static metadata points to release assets.

When: Install and offline rerun execute.

Then: Digests and authorization remain consistent across transports.

Required platform roles: portable.

## GH-005: Handle rate limits

Given: A fixture API returns rate limits and pagination.

When: The adapter refreshes metadata.

Then: Bounded retry and complete pagination preserve correct resolution.

Required platform roles: portable.

## GH-006: Handle changed locator

Given: A repository moves or an asset URL changes.

When: The client resolves a locked artifact.

Then: It accepts only the same authorized identity and digest.

Required platform roles: portable.

## GH-007: Dry-run publication

Given: A local publication plan is complete.

When: Dry run executes.

Then: No remote mutation or signing authority use occurs.

Required platform roles: portable.

## GH-008: Publish transactionally

Given: Authorized local fixture publication has multiple assets.

When: Upload fails before final metadata activation.

Then: No visible channel state advertises absent artifacts.

Required platform roles: portable.

## GH-009: Retry publication safely

Given: An identical publication partially completed.

When: The authorized operation retries.

Then: It detects existing identical assets and completes without conflicting state.

Required platform roles: portable.

## GH-010: Reject unauthorized publication

Given: No explicit publication grant exists.

When: A build or agent requests publication.

Then: The operation fails even when all tests pass.

Required platform roles: portable.

## GH-011: Smoke-test public transport

Given: The user authorizes a read-only public channel test.

When: The real GitHub adapter fetches it.

Then: Actual API behavior and verified digests are recorded without writes.

Required platform roles: host.
