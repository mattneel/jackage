# M17: Release hardening and independent evidence

These scenarios are product test designs, not executed tests.

## RELEASE-001: Replay clean checkout

Given: A release candidate and locks exist.

When: Independent CI rebuilds and tests from clean state.

Then: Results identify exact source, tools, platform, and executed commands.

Required platform roles: portable.

## RELEASE-002: Reject fake coverage

Given: Required cases contain only mocks, skipped tests, or documentation.

When: The release gate runs.

Then: It refuses full delivery.

Required platform roles: portable.

## RELEASE-003: Reproduce without result cache

Given: Equal declared release inputs exist on independent workers.

When: Both execute with fresh action results.

Then: Declared unsigned artifact bytes match or the claim fails.

Required platform roles: portable.

## RELEASE-004: Exercise recovery matrix

Given: Persistent operations have crash injection points.

When: The recovery suite interrupts them.

Then: Trust, store, profile, and lease state remain consistent.

Required platform roles: portable.

## RELEASE-005: Exercise malicious inputs

Given: Minimized parser, archive, metadata, and protocol attack fixtures exist.

When: Regression and bounded fuzz runs execute.

Then: No known crash, escape, or unauthorized acceptance remains.

Required platform roles: portable.

## RELEASE-006: Review dependencies

Given: The complete bootstrap and runtime dependency graph exists.

When: License and security review runs.

Then: Provenance and redistribution blockers are explicit.

Required platform roles: portable.

## RELEASE-007: Validate performance report

Given: Fixed benchmark definitions and raw measurements exist.

When: A reviewer reproduces the report.

Then: Claimed execution and reclaim results match evidence.

Required platform roles: portable.

## RELEASE-008: Publish support matrix

Given: Native evidence is missing for a target.

When: Release metadata and documentation are generated.

Then: The target remains unsupported or blocked rather than silently claimed.

Required platform roles: portable.

## RELEASE-009: Verify user documentation

Given: Installation, migration, recovery, and rollback instructions exist.

When: A clean disposable environment follows them.

Then: Commands match actual behavior and no undocumented manual step is required.

Required platform roles: portable.

## RELEASE-010: Retain publication boundary

Given: All release gates pass without production authority.

When: The final report completes.

Then: No public upload, push, signing operation, or paid resource creation occurs automatically.

Required platform roles: portable.
